1. Introduksjon

VærMonitor er et avansert analyseverktøy som bruker 8 uavhengige værvarslingsmodeller kombinert via Bayesiansk modell-gjennomsnitt (BMA) for å predikere daglige maksimumstemperaturer i 51 byer globalt.

Prediksjonene sammenlignes mot Polymarket.com sine temperaturmarkeder for å identifisere statistisk edge — situasjoner der markedet priser et utfall annerledes enn hva værmodellene tilsier.

Hva gjør VærMonitor unikt?

  • Multi-modell ensemble: ECMWF, GFS, ICON, GEM, UKMO, JMA, HRRR, og AIFS kombineres — ingen enkeltmodell dominerer.
  • Early peak detection: Systemet oppdager at dagens maksimumstemperatur er nådd før Polymarket-markedet justerer seg.
  • 3 parallelle strategier: Sigma (adaptiv), P5 (ultra-konservativ), Mean (50/50 referanse).
  • Helt automatisert: Pipeline kjører hver time via GitHub Actions, dashboard oppdateres automatisk.

3. Slik fungerer analysen

Steg 1: Værprognoser

Systemet henter daglige maksimumstemperatur-prognoser fra 8 uavhengige værmodeller via Open-Meteo sitt gratis API. Hver modell gir sin prediksjon for morgendagens maksimumstemperatur.

Steg 2: BMA Ensemble

De 8 modellene kombineres ved hjelp av Bayesian Model Averaging (BMA):

μ = Σ(w_i × μ_i)        Vektet gjennomsnitt
σ² = Σ(w_i × (σ²_i + (μ_i − μ)²))   Vektet standardavvik

hvor w_i er modell-vekten (ECMWF: 0.30, GFS: 0.20, ICON: 0.15, osv.)

BMA-modellen produserer:

  • μ (mean): Beste estimat for morgendagens maksimumstemperatur.
  • σ (std): Usikkerhet i prediksjonen.
  • P5–P95: 90% konfidensintervall.
  • Confidence: Hvor sikker modellen er (0-99%).

Steg 3: Strategi-generering

Basert på BMA-resultatene beregnes anbefalt spill-nivå for hver av 3 strategier (se Strategier).

Steg 4: Markeds-sammenligning

Systemet henter Polymarket-priser for temperatur-markeder og sammenligner:

edge = BMA_sannsynlighet − markedspris

🟢 BUY:  edge > 0  → BMA mener utfallet er mer sannsynlig enn markedet tror
🔴 SHORT: edge < 0  → BMA mener utfallet er mindre sannsynlig enn markedet tror
⚪ FLAT:  edge = 0  → Ingen edge

Steg 5: Peak Detection

Gjennom dagen overvåkes temperaturen i sanntid. Når dagens maksimum er nådd, bekreftes peak, og alle strategier avgjøres som WIN eller LOSS (se Peak Detection).

4. Strategier

VærMonitor evaluerer tre parallelle strategier for hver by, hver dag:

StrategiFormelWin-sannsynlighetStil
🎯 Sigma (μ−kσ) spill = ⌊μ − k × σ⌋ 62–84% Adaptiv — k justeres automatisk
🛡️ P5-Basert spill = ⌊P5⌋ ~95% Ultra-konservativ — nesten garantert gevinst
📊 Mean-Basert spill = ⌊μ⌋ ~50% Balansert — 50/50 referanse

🎯 Sigma-strategien (anbefalt)

Dette er hovedstrategien. Den trekker fra et sikkerhetsmargin (k × σ) fra BMA-gjennomsnittet. k-faktoren justeres dynamisk:

BMA ConfidencekWin-sannsynlighetForklaring
> 80%0.3~62%Høy confidence → aggressivt spill
70–80%0.5~69%Medium confidence → balansert
< 70%0.7~76%Lav confidence → konservativt
Sigma-strategien har historisk oppnådd ~60-75% win-rate. Den adaptive k-faktoren gjør at systemet er mer aggressivt når modellene er enige, og mer konservativt når de spriker.

Hvordan avgjøres WIN/LOSS?

Polymarket avgjør temperatur-markeder basert på avrundet faktisk maksimumstemperatur:

WIN  hvis round(faktisk_maks) == spill
LOSS hvis round(faktisk_maks) != spill

Eksempel: Hvis BMA predikerer 35.4°C og sigma-strategien anbefaler BUY 35°C, og faktisk maks blir 35.2°C → round(35.2) = 35 → WIN ✅

6. Markeds-edge

Markeds-edge er forskjellen mellom hva BMA-modellen predikerer og hva Polymarket-markedet priser:

edge = BMA_prob − market_prob   (i prosentpoeng)

Eksempel: Madrid 35°C
  BMA sannsynlighet: 62%  (BMA μ=35.4°C, σ=0.6 → P(round=35) = 62%)
  Markedspris:       45%  (Polymarket "Yes" = 45¢)
  Edge:             +17%  → 🟢 BUY — markedet undervurderer 35°C

Edge > 10% utheves med fet skrift. Dette er markedene med størst potensial.

7. Resolution Arbitrage

Resolution Arbitrage er en spesiell type mulighet som oppstår etter at peak-vinduet har passert og faktisk temperatur er kjent, men markedet fortsatt handler som om utfallet er usikkert.

Slik fungerer det

  1. Peak-vinduet passerer (f.eks. Madrid 15:00–18:00 → kl. 19:00 er peak passert).
  2. Faktisk maksimumstemperatur er kjent (f.eks. 36.1°C → vinner-bøtte = 36°C).
  3. Systemet scanner Polymarket for bøtter som fortsatt har feil pris.

To typer muligheter

TypeBetingelseProfitt
🔴 SHORT taper Taper-bøtte @ 1–50¢ Selg til gjeldende pris, få 100¢ ved resolution → profitt = 100 − pris
🟢 BUY vinner Vinner-bøtte @ 50–95¢ Kjøp til gjeldende pris, få 100¢ ved resolution → profitt = 100 − pris
Resolution arbitrage er tidskritisk — markedet kan korrigere seg når som helst. Handl raskt når muligheter dukker opp.

8. SMS-varsler

VærMonitor kan sende SMS-varsler via Twilio når en strategi er i fare.

Når sendes SMS?

  • BMA-confidence > 70% (modellen er sikker).
  • Sigma win-sannsynlighet < 50% (strategien er i fare).
  • Kun én SMS per by per dag (for å unngå spam).

Eksempel på SMS

VARSMONITOR: Madrid, ES peak sannsynlig (82%).
KJOP 35C star i fare (42% win prob).
Vurder SELG. (2026-08-10)

Oppsett

  1. Opprett konto på twilio.com
  2. Skaff Account SID, Auth Token, og et Twilio-nummer
  3. Sett som GitHub Secrets: TWILIO_SID, TWILIO_TOKEN, TWILIO_FROM
  4. Sett miljøvariabel ALERT_PHONE til ditt telefonnummer
Twilio gir $15 gratis kreditt ved opprettelse — nok til ~200 SMS. Test med python _sms_alert.py --test.

9. Pipeline

Hele systemet kjører automatisk via GitHub Actions. Du trenger ikke gjøre noe — pipeline går av seg selv.

Timeplan (UTC)

Tid (UTC)Hva skjer
Hver timehourly_active — BMA + peak check for byer i aktivt vindu
23:00daily_close — Hent arkivdata, avgjør ALLE 51 byer, generer rapport

Hva skjer ved hver kjøring?

  1. Systemet finner hvilke byer som er i sitt aktive vindu (04:00–peak_end+2 lokal tid).
  2. BMA kjøres for aktive byer (lead_days=0 = i dag).
  3. Peak detection sjekker om dagens maksimum er nådd.
  4. Hvis noen by er i peak-vindu → rapid peak monitor starter (3-min polling).
  5. Ved bekreftet peak → alle 3 strategier avgjøres (WIN/LOSS).
  6. Markedspriser hentes fra Polymarket.
  7. Dashboard (HTML) genereres og pushes til GitHub Pages.
  8. SMS-varsler sendes ved behov.

Tidssone-bevissthet

Pipeline er tidssone-aware — den prosesserer kun byer som er i sitt aktive vindu. Dette betyr:

  • Europeiske byer prosesseres ~04:00–16:00 UTC
  • Amerikanske byer prosesseres ~08:00–23:00 UTC
  • Asiatiske byer prosesseres ~19:00–01:00 UTC (neste dag)

10. Feilsøking

Dashboard viser gammel data

  1. Sjekk GitHub Actions — fullførte siste pipeline-kjøring OK?
  2. Vent 1–2 minutter (GitHub Pages har cache).
  3. Prøv Ctrl+F5 (force refresh) i nettleseren.

Ingen data i dashboard

  1. Sjekk at pipeline ikke har feilet: Actions → "Model Quality Pipeline".
  2. Hvis feil: sjekk loggen for feilmelding.
  3. Vanligste feil: Open-Meteo rate limit (gratis tier: 10,000 kall/dag). Vent til neste dag.

Feilmelding: "orjson is not installed"

pip install orjson

Feilmelding: ".env file not found"

Lag en .env-fil i vær monitor/ med minimum:

ENV=production
WEATHER_BMA_ENABLED=true
WEATHER_SATELLITE_ENABLED=false
WEATHER_ENSEMBLE_CONFIDENCE_FLOOR=0.5

Pipeline timeout

Hvis hourly_active times ut (etter 300 min = 5 timer): dette er normalt hvis peak-vinduet er langt. Pipeline fortsetter ved neste kjøring (neste time).

Korrupt loggfil

Hvis _model_quality_log.json er ødelagt:

Remove-Item _model_quality_log.json
python _model_quality_tracker.py --mode daily_bma
Å slette loggfilen fjerner all historisk data! Ta backup først hvis dataene er verdifulle.
